# Standalone Prism 0.3 contract

The architectural source is `prism_standalone_proxy_design.md`. The release implements direct execution, bounded map variants, focused lexical retrieval, draft/review/synthesis, vision/text preparation with final synthesis, and constrained Laya routing with optional cost/power model assignment. Dynamic joins and exact exhaustive reduction remain future work; optional bounded source re-extraction and structured reduction are implemented.

| Design boundary | Implementation |
| --- | --- |
| API ownership | FastAPI service with default bearer authentication and explicit process-level `--no-auth`; `/v1/chat/completions`, `/v1/models`, metadata traces, `/v1/prism/costs`, `/capacity`; one choice, text output and image input |
| Configuration | Individual `models/` connections with environment credentials and `profiles/` workflows; `start --profile` exposes one alias and loads only referenced models; legacy `serve --config` remains supported |
| Cost reporting | Configured per-million USD input/output rates, provider-usage spend since process start, unknown-cost counts, and explicitly estimated direct-baseline savings; no invoice or answer-quality guarantee |
| Backend adapter | LiteLLM SDK native/compatible calls with bounded HTTP guards; explicit limits/admission declarations, no SDK retries; configured policy repair is bounded and traced |
| Public identity | Virtual alias returned in completions/chunks; physical model IDs in traces |
| Compatibility gate | Known parameter allowlist; untransformed direct-only tools/logprobs/bias/seed/reasoning; unsupported features rejected |
| Source preservation | Immutable request-local content, SHA-256 identity, UTF-8 half-open spans, explicit user source blocks |
| Plan compiler | Eight finite policy templates; capability/context/coverage/resource preflight, checked vocabulary, dependencies, depth/node bounds |
| Model optimization | Optional JSON rating/price allowlist; request-local stage assignment, conservative cost/power ranking, bounded Laya task-fit bonus |
| Evidence | Typed fact/quote artifacts; quote uniqueness and provenance checks; partition completion/truncation/needs checks |
| Finalization | All validated map artifacts included in one synthesis, or optional bounded state/rolling reduction with evidence pointers; retrieval explicitly uses focused original spans |
| Resource ledger | Atomic reservations for call/input/output/cost bounds; pre-reserved finalization, deadline and cancellation accounting |
| Scheduling | Per-request bounded worker pool, per-backend semaphores, server admission backpressure; strict cross-request fairness is not claimed |
| CPU decisions | Required pip-installed Laya in a spawned CPU process; chooses only preflighted plans, bounded instruction sample, revision/question fingerprint, cancellation/reaping, rules fallback |
| Streaming | Direct SSE forwarding; adaptive and schema-constrained output buffered before emission; stable public identity and usage-only final chunks |
| Privacy | Metadata-only in-memory traces; no prompt/source logging, no cross-request artifact cache, credential-scoped access or shared anonymous scope with `--no-auth` |
| Evaluation | Paired benchmarks plus live bounded JSON/schema, pixel-vision, and reasoning probes on physical models and real profile graphs at `/capacity` |

Exact exhaustive reduction, dynamic joins, unbounded repair, persisted artifact caches, concurrent saturation profiling, Responses, audio/video modalities, and production tokenizer-specific adapters are not implemented. Exact count/exhaustive keywords in adaptive requests are conservatively rejected. This is a guard, not a general task-understanding classifier. A semantically exhaustive task without those keywords still requires operator/workload validation; map policies do not promise exhaustive extraction.

Without optimization, `auto` compiles every allowed feasible policy before Laya chooses among them. The fallback prefers direct when the original fits; otherwise batching for multiple documents, then evidence mapping. Focused profiles prefer retrieval when available. Map/retrieval plans require explicit sources; explicitly allowed `draft_review` instead requires source-free transformable text. Fixed strategies select one guarded policy and skip decision inference. Features requiring untransformed execution remain direct, and a profile excluding direct rejects them. Conversation histories involving assistant/tool messages are always direct. No route guesses source boundaries, silently truncates instructions, revives omitted conversation state, executes caller tools, or switches to an unconfigured endpoint.

Optimization-enabled profiles require a complete model rating/price allowlist. Each call may supply `context_management` objects with `prism_cost_priority` (0–1), narrower model/policy subsets, and tighter dollar/call ceilings. Controls never reach backends or public logical usage. The compiler checks assignments and retains the best per policy; Laya receives those complete candidate summaries. A validated recommendation supplies 10% task fit in the power score, and deterministic cost/power ranking chooses execution. Priority 1 selects the cheapest feasible plan. Shadow/abstention/failure supply no bonus. Settings and caches are request-local; legacy profiles are unchanged. This array is a Prism Chat Completions extension, not Responses or compaction support. See [model optimization](model-optimization.md).

`direct` uses one unchanged call. `evidence_map` uses one extractor per partition and one synthesis. `batched_map` groups partitions within context and configured batch limits, requires a complete typed result for each, and uses one synthesis. `verified_map` adds a verification call for every partition; every record ID must be checked without issues before synthesis. Rejected verification fails visibly unless one configured fresh source extraction succeeds and passes re-verification; replacements are traced. Optional reduction carries bounded observations and retrieves raw evidence from temporary Markdown files. Empty record sets are labeled without model verification or recall claims. `retrieve_read` selects lexically relevant original partitions within the final context and answers in one call; it requires `coverage: "focused"`, exposes selected/unselected spans, and forbids inferring global absence from the subset. Zero lexical matches fail visibly. See [execution policies](execution-policies.md).

`draft_review` drafts with the worker, obtains typed `issues`/`suggestions` from the verifier, and synthesizes the final answer. Original messages are retained at every stage; artifacts are untrusted data. Internal outputs must be untruncated text without tools/refusals, and both returned content and serialized artifacts must fit `intermediate_max_bytes` (default 4096). The whole graph, including downstream serialization envelopes, is preflighted and reserved before drafting. Failures abort without replacement or extra calls. This review supplies critique, not provenance or guaranteed correctness.

Explicitly permitted `vision_synthesis` uses an image worker and a text final model. `text_synthesis` uses plain-text observations to condense explicit source blocks. Each reserves two calls before dispatch and rejects incomplete/invalid intermediates. Observations are unverified and lossy; their coverage labels do not claim source-backed evidence or exhaustive recall. Images reach only the image worker in vision synthesis. A profile's validated `structured_output_model` selects its effective direct/final model for JSON-required requests; the public alias remains stable. Final JSON Schema is validated regardless of provider declarations. Image generation and additional omni modalities are not implemented.

Laya is required at installation and prepares at startup; model-loading failure prevents readiness. `route` is the default and `shadow` records proposals without changing execution. An untruncated eligible choice needs a finite option probability at least `min_option_confidence`. That threshold is not calibrated answer correctness. Inference errors, rejected proposals, and abstention preserve the preflighted rules fallback. Deadline/disconnect cancellation kills the CPU worker, and subsequent decisions fall back until restart. Laya cannot change the graph, endpoints, budgets, coverage, or evidence checks.

Source preservation lasts until request execution completes. The release does not expose a persisted corpus store. The caller supplies all content on every request. A filesystem path in a message does not grant file access. JSON Schema validation accepts local pointer references only and does not fetch remote schemas. Artifacts and HTTP/SSE buffers are size bounded.

Workers may miss facts or misinterpret valid quotes. Provenance and processed-partition coverage are separate from answer correctness. Incomplete worker outputs/needs abort unless configured bounded re-extraction succeeds; the release does not resolve arbitrary external dependencies. Adaptive output is useful for bounded evidence-backed summarization/QA after workload evaluation, not arbitrary proof or guaranteed global reasoning.

All prices and context/token bounds are declared by the operator. The ledger refuses hard dollar caps with missing prices; over-bound reported usage fails visibly. Unreported started work consumes conservative reservations and is traced as unknown. Local cancellation does not establish remote cancellation or zero provider cost. Admission semaphores limit backend dispatch but are not GPU-memory measurements.

The physical output cap includes backend reasoning tokens if the backend includes them in completion usage. Logical `usage` fields are byte-based diagnostic counts, fixed across routes. They must not be compared to billed model tokens or interpreted as token savings. There is no aggregate physical-token total that pretends different tokenizers are interchangeable.
