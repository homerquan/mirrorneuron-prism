# Standalone release validation — October 2, 2026

The 0.2.0 distribution implements direct proxying, bounded evidence-map execution, and optional pip-installed Laya shadow proposals. This report describes engineering checks, not general answer-quality or performance results.

Validation used Python 3.12 on macOS ARM64. The standalone/core and preserved legacy suites passed (198 tests); the opt-in real socket conformance test also passed (one test). Four opt-in endpoint/socket tests are excluded from the default run. The default suite does not contact model servers or download weights. CI additionally declares Python 3.11–3.13; those remote CI runs have not been observed in this work session.

Checks cover ordinary OpenAI SDK model discovery/completions/streaming, role preservation, output-limit spelling, JSON Schema buffering/validation, function tool forwarding, parameter rejection, authentication, upstream error sanitization, missing/truncated/invalid evidence, immutable UTF-8 span validation, full submitted partition coverage, context/resource reservations, deadline/client-disconnect cancellation, post-commit stream failures, and spawned CPU-decision worker cancellation/reaping. Source input beyond the configured worker admission window is exercised with a deterministic backend fixture. This establishes runtime bounds/coverage plumbing, not extraction recall or a physical model's maximum usable context.

The local Docker Model Runner endpoint in the existing JSON registry was reachable. Two small real prompts through Prism to `ai/gemma4:E2B` returned `prism`: one non-streaming and one SSE with a logical usage-only final chunk. A 32-token trial returned empty content with `finish_reason=length` because its completion budget was used before the final answer; the 256-token checks completed with `stop`. The proxy preserved that distinction and did not substitute reasoning text as the final answer.

A forced evidence-map request against the same physical model used three short synthetic deployment-policy documents. Three extraction calls produced validated quotes; one synthesis call returned an answer describing standard approval, emergency authorization/review, rollback, and outage-record obligations. Runtime coverage listed all three required partitions as validated, and the trace recorded four backend calls. This is a functional multi-call smoke test, not a long-context recall benchmark or evidence of equivalence to a stronger model. The Muse endpoint in the registry was unreachable, so no Muse or stronger-model comparison is claimed.

Laya 0.3.23 was installed from PyPI and imported successfully. Its checkpoint inference was not measured or calibrated in this session. The real process/pipe/cancellation lifecycle is covered using a deterministic model stub; actual Laya remains shadow-only. The parent ASGI process does not import Torch during normal startup/help. A checkpoint can be explicitly prepared at startup with a local path or pinned model revision/hashes.

Wheel and source distribution builds succeeded, and `twine check` accepted both artifacts. Archive inspection verified bundled JSON defaults, typing markers, legacy schemas, and project/third-party licenses; no model weights, local caches, or runtime traces were packaged. A clean temporary environment installed the wheel plus its normal dependencies, ran `prism --version`, generated JSON configuration, and validated it from outside the source checkout. Torch and LiteLLM were absent in that environment. Core metadata is pinned to version 2.4 for release-tool compatibility.

Before publishing, configure PyPI project ownership/Trusted Publishing and run the manual release workflow on the reviewed revision. Before making workload-level accuracy, latency, price, or virtual-context claims, run paired evaluations with appropriate ground truth, backend tokenizers, pinned checkpoints, calibrated routing evidence, and real deployment limits.
